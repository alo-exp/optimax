# Optimax product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Teams and individual practitioners building with Claude or Codex who want to delegate AI work across appropriate models and useful parallel tasks. The public site helps them understand the policy, inspect its evidence and install it; the Help Center answers setup and operating questions.

## Product Purpose

Optimax is an open-source delegation policy and thin plugin. It breaks work into bounded assignments, routes controllable helpers by task complexity and independently assessed performance, and maximizes useful parallel work within verified capacity. The user's chosen Orchestrator owns decisions, review and acceptance.

## Positioning

Approved hero: “Get AI work done faster and cheaper”. Approved subtitle: “Maximize parallelization, minimize cost”. Supporting copy connects task breakdown, useful parallelization, complexity-based routing, monitored subagent performance and independent review. Faster completion and lower model cost are desired outcomes, not measured savings or guaranteed mathematical minima.

## Operating Context

The existing static Node build emits public HTML, CSS and JavaScript. GitHub Pages serves https://alo-exp.github.io/optimax/; SITE_URL also supports a root-domain build. Installation commands, activation controls, search, existing routes and fragments are functional contracts. The source has 17 Help Center articles and 40 indexed sections.

## Capabilities and Constraints

- Preserve the approved homepage copy and Help Center content during the visual redesign; preserve real proof links, install commands and behavioral controls.
- Independent ready work may run concurrently only when capacity, dependencies and exclusive resources allow it. Conflicting writes and consequential shared operations remain serialized.
- Exact helper settings and attributable independent assessments determine learning. Opaque native workers are outside verified optimization.
- The site must offer dark and light themes. The latest explicit user brief makes dark the default; retain an explicit saved light or dark choice.
- Keep project-prefix URLs, accessibility, readable documents, reduced-motion behavior, responsive layouts and static deployment intact.

Claude currently has static package validation with live acceptance deferred. No customer testimonials, usage totals, performance benchmarks or quantified savings are supplied; do not invent them.

## Product Principles

- Explain the mechanism and limits in plain language.
- Pair useful parallel work with quality-based routing.
- Preserve the user's chosen Orchestrator and explicit controls.
- Make proof inspectable and acceptance independent.

## Accessibility and Inclusion

Use semantic controls, keyboard navigation, meaningful labels, visible focus, readable contrast, reduced-motion support and responsive reflow. Help articles prioritize comprehension and wayfinding over visual performance.
