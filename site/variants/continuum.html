WHY THE PLAN MATTERS

When independent assignments wait their turn, the whole job takes longer. When every assignment goes to the same model, model effort can be out of proportion to the task. And when nobody checks how the pieces fit, you inherit the integration work.

Optimax gives your agent a policy for all three decisions: what can run together, which helper should do each piece, and what must be checked before the result is accepted.

It is most useful for substantial work with independent pieces. Work that truly depends on an earlier result still waits for that result to pass review.

HOW OPTIMAX WORKS

The plan connects delegation to the outcome you asked for. Independent work can move together; shared files and dependent steps keep their order.

  1. 01

    Define what a good result looks like

    Give each helper a clear outcome, acceptance criteria and its own scope. Identify the inputs it needs and the files or resources it owns, so parallel work has a safe boundary.

  2. 02

    Match the helper and run ready work

    Choose eligible models and effort levels using task complexity and independently reviewed performance. Run useful, compatible assignments within verified capacity. Start the next eligible task as soon as its accepted inputs and resources are available.

  3. 03

    Review the work, then learn from it

    Your chosen session model independently checks each result and its evidence. Accepted work unlocks the next step. Attributable assessments inform future model choices; work that needs repair goes back for another pass.

WHAT THE POLICY HELPS YOU DO

Keep useful work moving

Independent tasks can run together, and eligible follow-up work can start while unrelated tasks continue. You spend less of the plan waiting for work that does not block the next step.

Use model effort with a reason

Task complexity and reviewed results guide model selection. You can direct effort where the assignment calls for it, rather than treating every piece of work as equally demanding.

Make “done” mean checked

Each assignment has an owner and acceptance criteria. Independent review checks the result and evidence before dependent work moves on, so a helper's completion message is the start of acceptance, not the whole process.

BEFORE YOU INSTALL

Will Optimax change the model I chose?

Your chosen session model stays in charge of the plan, review and acceptance. Optimax can recommend a model and effort for that role, but it does not apply the recommendation or change native settings for you.

Does it always pick the cheapest helper?

No. Task complexity, eligible settings and independently reviewed performance guide the choice. Price alone does not establish suitability. Faster work and lower model cost are goals, not guaranteed savings.

How many tasks can run at once?

As many useful, independent assignments as verified capacity supports. Dependencies must be accepted and shared resources must be compatible. Reviewers, advisers and rework also use capacity. If native occupancy is unknown, Optimax cannot treat those slots as available.

What happens when a result needs more work?

It goes back for bounded repair and another independent review. Dependent tasks wait for an accepted result. A good model score does not turn an incomplete job into an accepted result.

Can it manage every helper inside Claude or Codex?

Only where the host exposes the necessary controls and effective model settings. Hidden worker settings cannot support verified model comparisons or learned scores. Native orchestration is only partly optimizable when those facts are unavailable. Read the native mode limits.

Can I turn it off?

Yes. Use $optimax off in Codex or /optimax:optimax off in Claude to stop policy-driven delegation, consultation and learning. Useful work already in flight can finish safely. Your performance history and native settings are preserved. See on, off and status controls.

Do I need it for every small task?

Optimax is most useful when work has several meaningful pieces to delegate. A small, tightly connected task may have little useful parallel work. The policy calls for meaningful assignments, not extra helpers for their own sake.

Look at the whole job

Running more helpers addresses only part of the task. Optimax brings parallel work, model selection and independent acceptance into one policy, so decisions about time and model effort stay tied to the result you asked for.

FREE PLUGIN / MIT LICENSE

The plugin is free and MIT licensed. Your account's host and model usage charges still apply.

You get the delegation policy, session controls and a project record of independently reviewed helper results. Install it through your host's plugin marketplace, then enable it in the session where you want to use it.

Check installation and host support

Installing the plugin does not turn the policy on. You can inspect the source first and turn it off with the session controls whenever you choose.

AFTER INSTALLATION

Enable Optimax with $optimax on in Codex or /optimax:optimax on in Claude. Describe the result you need and how you will judge it. Your agent can then define the assignments, find useful parallel work and review the results.

Check the session with $optimax status or /optimax:optimax status to see the current mode and reported limits.
